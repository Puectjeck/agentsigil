# AgentSigil

**A free daily sigil for Agent ID holders** — an entry for the Binance Wallet ×
BNB Chain **Agent ID Hackathon** (submission period 2026-11-18 08:00 UTC →
2026-12-09 08:00 UTC).

Once per UTC day, a wallet holding a SPACE ID **Agent ID** (`name.ai`) can call
`claim()` on the AgentSigil contract (BNB Smart Chain) and mint a **soulbound**
(non-transferable) ERC-721 sigil. The sigil's artwork is an SVG generated and
stored entirely on-chain, showing the claimer's current **streak**
(consecutive UTC days claimed), their **total claims**, and the claim day.
Missing a UTC day resets the streak to 1 on the next claim.

There is no fee, no deposit, and nothing to buy. Claiming costs only the
network gas of the claim transaction itself, which each user reviews and
confirms in their own wallet.

## How Agent ID is used

Agent ID is the contract's **core access mechanism**, not an add-on:

- The Agent ID contract is SPACE ID's Agent ID registry on BNB Smart Chain:
  `0x60B9262456dE011F7d15a54CdD8c48bAaa8B022F` (ERC-721, non-transferable).
- `claim()` calls `balanceOf(msg.sender)` on that contract **inside the claim
  transaction** and reverts unless the result is `> 0`. There is no allowlist,
  no signature, and no off-chain check to bypass: holding an Agent ID is the
  only way in.
- The frontend's `stateOf(address)` helper performs the same read so visitors
  can see their Agent ID status before claiming.
- Because a sigil can be claimed once per day and streaks reward consecutive
  days, Agent ID holders have a reason to return and transact daily — Agent ID
  becomes a living identity with a visible on-chain history, rather than a
  name that sits idle.

## The contract

`contracts/AgentSigil.sol` — a hand-rolled, minimal ERC-721 (no external
dependencies), MIT-licensed.

- **Soulbound.** `transferFrom`, both `safeTransferFrom` overloads, `approve`,
  and `setApprovalForAll` always revert. ERC-5192 is implemented
  (`locked(tokenId)` always returns `true`, `Locked` event at mint) so wallets
  can detect the soulbound status.
- **Daily claim.** One claim per wallet per UTC day
  (`lastClaimDay < today`, where `today = block.timestamp / 86400`).
  Streak = previous streak + 1 if yesterday was claimed, otherwise 1.
- **Counters.** `totalClaims()`, `uniqueClaimers()`, `totalSupply()`, plus
  per-user `streakOf` / `totalClaimsOf` and per-token snapshots
  (`tokenDay`, `tokenStreak`, `tokenTotalClaims`).
- **On-chain metadata.** `tokenURI` returns `data:application/json;base64`
  with an embedded `data:image/svg+xml;base64` image generated by the
  contract — no IPFS, no server.
- **Events.** `Claimed(user, tokenId, day, streak)`, standard ERC-721
  `Transfer` on mint, ERC-5192 `Locked`, `Paused` / `Unpaused`.

### Owner permissions (complete list)

The owner is **not** the deployer. The constructor takes an explicit
`initialOwner` address:

```solidity
constructor(address initialOwner)
```

- At production deployment, `initialOwner` =
  **`0x4A5944DDf10C5426C39b20b059e340b4E81a98b6`** (Jon's Binance Agentic
  Wallet). The deployer is a separate burner EOA that only broadcasts the
  creation transaction; after deployment it holds **no** power over the
  contract and cannot regain any.
- The owner's **only** powers are:
  - `pause()` — stop new claims (safety switch);
  - `unpause()` — resume claims.
- The owner **cannot**: mint sigils, withdraw anything (the contract holds no
  funds and `claim()` is non-payable), change the Agent ID contract address
  (it is a compile-time constant), transfer ownership (no such function),
  or alter existing tokens. There is **no proxy and no upgrade mechanism**.
- After deployment, the owner can call pause/unpause from the Agentic Wallet
  via `baw contract-call` (preview, then execute):
  - pause: `--to <AgentSigil address> --value 0 --inputData 0x8456cb59`
  - unpause: `--to <AgentSigil address> --value 0 --inputData 0x3f4ba83a`

### Safety / hackathon red-line compliance

- Users connect **their own** wallet in their own browser and confirm every
  transaction themselves. **No QR-code sign-in**, no pairing codes, no
  sessions held by the project.
- The contract and site **never** ask for seed phrases, private keys, or
  pairing codes, and never request any approval (the sigil contract itself
  rejects approvals).
- No automatic or unauthorized transfers; the only asset movement is a sigil
  minting to the claimer's own wallet.
- No returns are promised anywhere — a sigil is a keepsake record, and the
  site copy says so plainly.
- Agent ID is used purely as a self-gate (`balanceOf` of the caller). The
  project does **not** look up other people's wallets by name.
- The name "AgentSigil" does not use the Binance or BNB brand.

   `0x1F1Cb24B014Ff409d592558D69358FF4DCbfDBe4`. Send it **~0.0002 BNB**

   (Jon's Agentic Wallet), reads back `owner()` to confirm, and writes
   `build/deployed.json`.

   deployer); `stateOf(deployer)` works; one test claim from an Agent ID

## Frontend

- **Intended public repository:** https://github.com/Puectjeck/agentsigil
  (not yet created — the GitHub connector returned `403 Resource not
  accessible by integration` on 2026-11-19).
- **Intended website:** https://puectjeck.github.io/agentsigil/
  (not yet live — the URL returned HTTP 404 on 2026-11-19 because the
  GitHub Pages user-site repository had not been created).

`app/index.html` is a single static file. It loads ethers v6 from a CDN,
connects the visitor's own injected wallet (`window.ethereum`), switches to
BNB Smart Chain (56), reads `stateOf()` + `paused()` + global counters, shows
Agent ID status / streak / total claims / a live countdown to the next UTC
day, and sends `claim()` from the visitor's wallet when they press the Claim
button (the visitor confirms in their own wallet). It also reads the
`paused` flag and the Agent ID flag separately, so the button is disabled
with a plain explanation when claims are paused or no Agent ID is held.
